# 0012 -- FreqO1: a worst-case-O(1) LFU frequency primitive over a PRIVATE bucket forest, a FIFO tie-break, a lean surface (no decrement / no peekMax / no delete), the 2^32-2 frequency ceiling, and a bucket-pool sized to the transient peak

Status: accepted (v0.7.0)

## Context

O(1) LFU (least-frequently-used) eviction is a real need (caches, admission
controllers, hot/cold classification, frequency sketches). The textbook O(1)-LFU
structure (Shah/Mishra/Matani) is a doubly-linked list of frequency BUCKETS, each
holding a doubly-linked list of the keys at that frequency; the head bucket is the
minimum, so peek/pop of the least-frequently-used key is O(1), and an access moves a
key one bucket over in O(1). The standard implementation allocates a node object per
key and a bucket object per frequency -- exactly the per-op garbage lite-o1 forbids.
The question was how to ship that structure as a zero-GC, worst-case-O(1) member.
Five decisions had to be settled:

1. Where do the per-key NODES and per-frequency BUCKETS live -- a public SlotPool, or
   a private pool inside FreqO1?
2. What is the tie-break when several keys share the minimum frequency?
3. What is the surface -- full LFU cache, or a lean frequency primitive?
4. What is the frequency ceiling, and what happens at it?
5. How is the bucket pool sized so its free-list cannot be exhausted?

## Decision

**A PRIVATE internal node + bucket pool; NO public SlotPool; ADR 0003's SlotPool
deferral STANDS.** FreqO1 owns its substrate outright, over flat `Uint32Array`
columns, and exports no allocator. The KEYS ride SparseSet's dense + sparse
cross-check verbatim (`_dense[i]` is the key at dense index i, `_sparse[k]` maps
back, membership is `_sparse[k] < _n && _dense[_sparse[k]] === k`), and the dense
index i IS the stable node identity the intrusive lists use -- so `clear()` stays
O(1) (reset the count; the cross-check voids stale entries). Per KEY (indexed by
dense index): `_freq` (the count, >= 1), `_bkt` (its bucket), and `_nk` / `_pk` (an
intrusive doubly-linked FIFO key list within a bucket; NIL is the top uint32,
`FREQ_NIL`, since 0 is a valid dense index). Per BUCKET (a 1-based pool, bucket 0 =
NIL): `_bFreq`, `_bPrev` / `_bNext` (buckets sorted ASCENDING by frequency), and
`_bHead` / `_bTail` (FIFO oldest / newest key node, for O(1) head-pop + tail-append).
`_head` is the head of the bucket list -- the MIN-frequency bucket -- so peekMin /
popMin are O(1). Shipping a public SlotPool now would (a) reopen ADR 0003's deferral
(reconcile against `@zakkster/lite-arena` first) before its consumers exist, and (b)
couple FreqO1 to a shared substrate, breaking the "import one, drop the rest"
tree-shaking guarantee every other member keeps. A self-contained private pool is
the price of an independently tree-shakeable member that carries only its own cost.

**FIFO / insertion-order tie-break.** At equal frequency, peekMin / popMin return the
EARLIEST-INSERTED key in that frequency bucket. Each bucket's key list is appended at
the TAIL and popped from the HEAD, so the head is the oldest arrival to that bucket;
an increment re-stamps the moved key as the NEWEST at its new frequency (append at the
target's tail). This is the standard LFU-with-LRU-tie-break -- the least-recently
arrived among the least-frequently-used is evicted first -- and it is fully
deterministic, which makes the differential fuzz oracle (a `Map` of `key -> {freq,
tick}` with a global monotonic tick, min-freq then min-tick) exact.

**A LEAN frequency PRIMITIVE, not a full LFU cache.** The surface is exactly
`add` (track at frequency 1 if absent, idempotent no-op if present -- it does NOT
bump), `increment` (record one access: insert at 1 if absent, else freq += 1),
`frequencyOf` (the count, or 0 if absent / bad -- NEVER throws, 0 = not tracked is
the correct frequency), `has`, `peekMin`, `popMin`, `clear`, `forEach`,
`[Symbol.iterator]`, and the `size` / `capacity` / `universe` / `maxFrequency`
getters. Deliberately ABSENT: **no `decrement`** (aging is a caller policy, not a
primitive -- rebuild or clear + refill), **no `peekMax`** (the LFU victim is the
minimum; a maximum would double the bucket-end bookkeeping for a need this member
does not serve), and **no `delete(k)`** (the only removal is popMin, the eviction
op -- an arbitrary delete would need a second cross-checked removal path for no LFU
purpose). FreqO1 holds COUNTS, not payloads: to build a full LFU cache, keep the
values in a parallel SoA column or `@zakkster/lite-arena` and let FreqO1 pick the
victim key.

**`MAX_FREQ = 2**32 - 2`, fail closed.** Frequencies live in a `Uint32Array` slot.
The ceiling is 2^32-2, NOT 2^32-1, because the increment hot body writes `freq + 1`;
capping the reachable value at 2^32-2 keeps that bump inside the uint32 domain. There
is NO 0-is-absent sentinel on `_freq` -- the dense/sparse cross-check (not a freq
value) decides liveness, so a live key's frequency is simply >= 1. An increment that
would exceed `maxFrequency` throws `[lite-o1]` rather than wrap; the throw precedes
every state write, so it is a byte-identical no-op. `maxFreq` is a ctor arg (default
2^32-2) so a caller can pin a smaller ceiling and fail closed early.

**The bucket pool is sized to the TRANSIENT PEAK, so its free-list CANNOT be
exhausted under the contract.** The pool is a bump pointer (`_bBump`) plus a free
stack (`_bFree`) -- the same discipline SparseSet uses for keys -- so `clear()`
resets it in O(1) (`_bBump = 1`, empty the free stack; each bucket re-initialises its
fields on allocation, so stale bytes never leak). SIZING PROOF: the non-empty buckets
PARTITION the live keys by frequency (each holds >= 1 key), so at REST the number of
buckets is `<= _n <= capacity`. A single `increment` on a present key allocates the
target bucket (frequency f+1) BEFORE unlinking + freeing an emptied source bucket, so
the count TRANSIENTLY peaks at `(buckets before) + 1 <= _n + 1 <= capacity + 1`. The
pool therefore holds **capacity + 1** usable buckets, which is `>=` the transient
peak -- so `_allocBucket` always succeeds and exhaustion CANNOT happen under the
contract. The `_poolExhausted` throw remains as a fail-closed guard (the source law:
fail closed on every unverified state), defense in depth that the contract proves
unreachable.

**Fail closed, mirroring the suite.** A bad key (non-integer, NaN, null, Symbol,
BigInt, >= universe) throws `[lite-o1]` on the MUTATORS `add` / `increment`
(typeof-guarded BEFORE the coercing `>>>`, so a Symbol / BigInt never reaches
arithmetic; the cold message uses `String(k)`), but is ABSENT for the QUERIES `has` /
`frequencyOf` (never throw). `null` is not zero -- `(null >>> 0) === null` is false.
`-0` aliases key 0 via the uint32 coercion. A NEW key past capacity throws a
byte-identical no-op; `peekMin` / `popMin` on an empty structure return `undefined`
(never throw -- the sentinel is unambiguous because every stored key is a real
uint32). The ctor typeof-guards all three args and names the offender with
`String(x)`.

## Consequences

- `add` / `increment` / `frequencyOf` / `has` / `peekMin` / `popMin` / `clear` are
  ALL WORST-CASE O(1), zero allocation after construction -- proven by the torture
  gate (0 B/op on an increment + popMin churn -- a `freqBpc` metric -- `maxMajor` 0,
  arrayBuffers delta 0) and the perf gate (a `freqGrows` 0-delta counter on ALL
  backing `Uint32Array` columns across increment-churn / popMin-drain / forEach-drain).
- The witness shows `increment` + `peekMin` staying FLAT from size 1e3 to 1e5 while a
  naive frequency table that linearly scans all n counts to find the LFU key
  (O(n)/query) collapses. There is NO MAX-single-op line: every hot op is worst-case
  O(1) (a fixed number of pointer writes on the bucket forest, never a run), so the
  flat line IS the worst-case claim -- like MinStack and RandomSet, unlike the
  amortized MonoDeque.
- `forEach` scans in DENSE STORAGE order (insertion order, permuted by a popMin
  swap-remove -- NOT frequency order), re-reading `_n` each step so a re-entrant
  popMin from inside the callback self-terminates rather than reading out of bounds
  (the same live-scan discipline SparseSet / RandomSet document). `[Symbol.iterator]`
  is the one per-protocol allocator, kept out of the zero-alloc claims.
- FreqO1 stores integer KEYS + their access frequency in `[0, universe)`, not
  payloads. It is the LFU frequency PRIMITIVE, not a cache; compose it with a parallel
  value store for a full LFU cache.
- Memory cost: six `Uint32Array` columns sized to capacity (keys + node columns) plus
  five sized to capacity + 2 and one to capacity + 1 (the bucket pool) plus the
  universe-sized `_sparse`. That is the honest price of a pointer-free, zero-GC bucket
  forest with an O(1) clear -- more per-key memory than a bare count array, in
  exchange for a worst-case-O(1) min and zero per-op garbage.
